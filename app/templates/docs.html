PatchPilot Documentation

PatchPilot is an open-source, Bring-Your-Own-Key (BYOK) GitHub App for automated pull request code reviews and threaded interactive copilot conversations.

BYOK Security & Data Custody

All user API keys are encrypted at rest using AES-256-GCM with a 32-byte secret and randomized 96-bit nonces. Keys are decrypted exclusively in volatile RAM during pull request webhook execution and wiped instantly.

CIPHER AES-256-GCM
ISOLATION Per-GitHub Owner
RAM RETENTION 0ms Post-Diff

Interactive PR Copilot Commands

Trigger on-demand actions by tagging @PatchPilot in any pull request comment thread.

/review Full Pull Request Audit

Performs a comprehensive, line-by-line review across all changed files against your repository review policy. Automatically filters lockfiles, assets, and vendor noise.

Output Payload:
• Summary of changes & architectural impact
• Severity-ranked issues (Security, Concurrency, Performance)
• Ready-to-commit GitHub suggestion blocks
/explain Plain-English Architecture Narrative

Explains the intent, logic flow, and breaking changes in plain English. Ideal for onboarding teammates or non-technical product leads reviewing PRs.

/fix Actionable Code Patch

Reply to any PR comment with @PatchPilot /fix to receive a direct GitHub suggestion block that can be committed in one click.

/test Edge-Case Unit Test Generator

Generates framework-aware unit tests (pytest, Jest, Go) covering null checks, timeout boundaries, and error branches introduced by the PR diff.

Custom Review Policies

Configure custom rules in Markdown directly inside your BYOK Vault. PatchPilot appends these instructions into the system prompt for every review cycle.

# Example Policy
- Enforce strict typing on public API signatures.
- Flag unindexed queries and O(N^2) loops on request handlers.
- Reject plaintext secrets and verify CORS headers.

Sequential Multi-Key Failover Pipeline

Free-tier LLMs periodically hit rate limits (429), daily credit depletion (402), or temporary upstream outages (500/502/503/529). PatchPilot solves this with automatic, sequential provider failover:

1. Primary Execution

PatchPilot first attempts the review using your primary provider (e.g. Gemini 2.5 Pro).

2. Trigger Detection

If the primary returns status 401, 402, 403, 404, 429, 500, 502, 503, 529 or times out, the failover pipeline immediately catches the error.

3. Clean Failover Notice

PatchPilot seamlessly switches to your secondary fallback (e.g. Groq Llama 3.3 70B), completes the review, and annotates the GitHub PR summary card with a sanitized badge without exposing internal URLs or tokens.
