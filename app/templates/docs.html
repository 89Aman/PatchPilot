Documentation & Review Guide

Start with one repository and a small pull request. You’ll need permission to install a GitHub App and access to the model you want to use.

Get a review on GitHub

  1. Install the app

    On the GitHub installation screen, choose an account and a repository. For an organization, an owner may need to approve the installation.

  2. Connect a model

    Open the dashboard and sign in with the GitHub identity associated with your repository. Select the owner, choose a provider and model, and enter the provider key. Select Save Credentials, then test the saved connection.

  3. Open the pull request

    Open a non-draft PR with a small code change. Look for PatchPilot’s review in the PR conversation and findings beside the changed lines. To request a fresh review, comment @patchpilot review.

Ask in the review thread

@patchpilot review
Start a full review from the PR conversation.
@patchpilot explain
Reply to a line comment and describe what you want explained.
@patchpilot fix
Ask for a suggested change. Inspect the suggestion before applying it.
@patchpilot test
Ask for tests for the change under discussion.

Choose where the diff goes

With a hosted model, PatchPilot sends review context to the provider you configure. Provider usage and retention terms apply. For local inference, self-host PatchPilot and point it at an Ollama server reachable from the application.

Fallback keys

Add a secondary credential in the dashboard if you want another model to handle a review after a provider failure. Choose a provider that may receive the same review context.

Review policy

Use the dashboard’s custom review policy to record a team rule, such as “Flag schema changes that need a migration.” Save the credentials and policy before requesting a fresh review.

When a review doesn’t appear

Repository missing
Check the GitHub App installation’s repository selection and the account you used to sign in.
Model connection failed
Check the model ID, provider key and available quota. For Ollama, check the endpoint from the host running PatchPilot.
PR is quiet
Check that the PR is open and out of draft. From the PR conversation, have a repository collaborator post @patchpilot review. Self-hosters can check GitHub App webhook deliveries for the request and response.
